## User Datagram Protocol

- nützlich und wichtig bei Anwendungen mit geringer Latenz und hoher Geschwindigkeit
- Datenintegrität ist weniger wichtig
- Transportschicht (Schicht 4)
- arbeitet im datagram mode -> verbindungsloses Protokoll

## wesentliche Kennzeichen

- minimaler Protokoll-Overhead
- keine Garantie für Ablieferung der Daten oder richtiger Reihenfolge
- keine Vorkehrung gegen Duplikate
- Best Effort-Service

## UDP-Header

### Bestandteile

- Quell-Port (16 Bit)
- Ziel-Port (16 Bit)
- Length (16 Bit)
- Checksum (16 Bit) (optional)

### UDP Eigenschaften

- Headergröße 8 Byte
- sitzt auf IP-Protokoll 
- UDP muss in den IP-Datenteil passen
	- Maximalgröße von UDP ohne Header = 65508 Byte
	- errechnet aus 65536 Byte - 8 Byte (UDP-Header) - 20 Byte (IPv4-Header)
- IPv6 besitzt keine eigene Checksum
	- damit wird die Checksum von UDP bei IPv6 genutzt
- bei fehlerhaften Checksum -> Datagramm wird verworfen
- Best Effort-Service -> keinerlei Garantie für den Transport und Reihenfolge der Daten
- geeignete Dienste:
	- Echtzeit-Dienste (VoIP, IP-TV)
	- Dienste bei denen es auf Schnelligkeit ankommt (DNS)

## wesentliche Unterschied TCP - UDP

| TCP                                       | UDP                                         |
| ----------------------------------------- | ------------------------------------------- |
| verbindungsorientiert                     | verbindungslos                              |
| korrekte Reihenfolge der Daten garantiert | Reihenfolge der Daten nicht garantiert      |
| Datenflusssteuerung                       | keine Datenflusssteuerung                   |
| nur Punkt-zu-Punkt-Verbindung             | auch Multicast (Punkt-zu-Mehrpunkt) möglich |
| Bei Fehlern Ü-Wiederholung                | bei Fehlern keine Ü-Wiederholung            |
| Duplikate werden erkannt und verworfen    | Duplikate werden nicht erkannt              |
