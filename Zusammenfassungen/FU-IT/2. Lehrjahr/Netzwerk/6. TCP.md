- Transmission Control Protocol
- Daten werden zuverlässig, geordnet und vollständig übertragen
- Typische Protokolle:
	- HTTP, HTTPS, FTP, SSH, SMTP, IMAP

## Grundprinzip von TCP

- arbeitet verbindungsorientiert
	- bevor Datenübertragen wird eine Verbindung zwischen Sender und Empfänger übertragen
- TCP stellt sicher:
	- Daten kommen vollständig an
	- in der richtigen Reihenfolge
	- verlorene Daten werden erneut übertragen
	- Sender überlastet Empfänger nicht
	- kontrolliertes Auf- und Abbauen der Verbindung

## Three-Way-Handshake

### Ablauf:

1. SYN

- Client sendet SYN an Server

2. SYN-ACK

- Server antwortet mit Syn, Ack

3. ACK

- Client bestätigt mit Ack

## Datenübertragung

### Sequenznummern

- stellt die richtige Reihenfolge sicher
### Bestätigung

- ACK bei empfangenen Daten
### Erneutes Senden

- fehlender Daten werden erneut gesendet
### Flusskontrolle

- Vermeidung von Überforderung langsamerer Empfänger (Window Size)
### Staukontrolle

- Reduzierung der Sendegeschwindigkeit bei starker Netzwerkbelastung

## Verbindungsabbau

### Ablauf:

1. FIN

- Client sendet FIN an Server

1. ACK + FIN

- Server antwortet mit ACK dann FIN

3. ACK

- Client bestätigt mit ACK

## TCP im Vergleich zu UDP

| Merkmal          | TCP                                 | UDP                               |
| ---------------- | ----------------------------------- | --------------------------------- |
| Verbindung       | Verbindungsorientiert               | Verbindungslos                    |
| Zuverlässigkeit  | Hoch                                | Geringer                          |
| Reihenfolge      | Wird sichergestellt                 | Wird nicht sichergestellt         |
| Fehlerkorrektur  | Ja, durch erneutes Senden           | Keine automatische Wiederholung   |
| Geschwindigkeit  | Etwas langsamer                     | Schneller                         |
| Typische Nutzung | Webseiten, E-Mail, Dateiübertragung | Live-Streaming, Gaming, DNS, VoIP |
