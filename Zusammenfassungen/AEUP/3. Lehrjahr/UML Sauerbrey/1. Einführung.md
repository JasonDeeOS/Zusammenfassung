## Objektorientierte Programmierung OOP

### Prozedurale Programmierung

- sequenzielle Abarbeitung von Befehlen

### Objektorientierte Programmierung

- Ereignisse lösen sofort Aktionen aus
- an keine Sequenz gebunden
- wichtig sind Objekte, welche auf Ereignisse reagieren
- Objekte besitzen Eigenschaften (Attribute) und Funktionen (Methoden)

## Grundprinzipien der OOP

### Datenkapselung

- Attribute und Methoden sind in Objekte zusammengefasst
- Zugriff auf Daten durch Methoden
- Es werden Sichtbarkeiten für Methoden innerhalb eines Objekts festgelegt; Definition des Zugriffs auf diese Methoden

### Vererbung

- Klassen sind Baupläne für Objekte und können von anderen Klassen erben, wodurch sie die Eigenschaften und Methoden der Basisklasse übernehmen
- Dies fördert die Wiederverwendbarkeit von Code und ermöglicht die Schaffung einer Hierarchie von Klassen

### Polymorphie

- Objekte unterschiedlicher Klassen können über die gleiche Schnittstelle angesprochen werden
	- Methoden können dadurch überschrieben oder implementiert werden
	- erlaubt eine verschiedene Implementierungen einer Methode auf verschiedene Arten je nach Objekt
- Art und Weise des Zugriffs auf eine Methode kann sich zur Laufzeit ändern (Polymorphie)

### Abstraktion

- Implementierung wird verborgen und notwendiges ist öffentlich verfügbar
- reduziert Komplexität und hilft dem Entwickler, sich auf Wesentliches zu konzentrieren

## Unified Modeling Language (UML)

- standardisierte grafische Sprache
- Visualisierung, Spezifikation, Konstruktion, Dokumentation von Softwaresystemen
- Darstellung komplexer Softwarestrukturen
	- verschiedene Phasen der Softwareentwicklung können damit modelliert werden
	- zB Anwendungsfalldiagramm, Klassendiagramm
- Diagramme helfen zu dokumentieren und Qualität zu sichern
- Prüfungsrelevant sind:
	- Anwendungsfalldiagramm
	- Aktivitätsdiagramm
	- Klassendiagramm
	- Zustandsdiagramm
	- Sequenzdiagramm
